LSM write amplification

A small model of how RocksDB takes writes. Each put hits the WAL, fills a 4 key memtable, then flushes to L0 and gets merged down by compaction. Compaction rewrites data already on disk, so write amplification keeps climbing. Press auto, then hover the chart.

About me

I started in data science, but I kept getting curious about what happens underneath: where a byte goes when I call write(), why one lock makes a program slow, how the kernel picks the next task. So I started building those layers myself.

I like projects where I can measure something and then make it better. I work in C++ and use Linux tools like perf and eBPF, and I try to back every idea with a benchmark.

Outside of systems, I built my own PC, I have worked on campus before, and I am slowly leveling up my competitive programming.
