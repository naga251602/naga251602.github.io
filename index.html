01

Durable DB

In progress

A database, from the bytes up.

Intermediate · C++ · Linux
+

Build a persistent key-value database from scratch in C++ without relying on an existing storage engine.

Planned scope

  • Binary serialization and deserialization
  • File-backed put(), get(), remove()
  • Fixed-size 4 KB storage pages
  • B-tree or B+ tree indexing
  • Write-ahead logging and crash recovery
  • Buffer pool with LRU eviction
  • Concurrent reads and writes (extension)
  • Performance benchmarks

Tech stack

C++20 · Linux · POSIX I/O · pread / pwrite / fsync
B+ trees · Hash maps · LRU
CMake · GCC / Clang
GDB · Valgrind · Sanitizers
GoogleTest · Google Benchmark · perf
Target deliverable

A crash-recoverable database with verified persistence, indexing, caching, and documented benchmark results.

03

PulseFeed

Planned

Every message. Every microsecond.

Advanced / Networking · C++ · Linux
+

Build a low-latency engine that receives, processes, and distributes simulated financial market data.

Planned scope

  • TCP / UDP sockets and UDP multicast
  • Nonblocking I/O and epoll
  • ITCH-inspired binary packet decoding
  • Sequence tracking and gap detection
  • Snapshot recovery with a simulated feed
  • SPSC lock-free ring buffer
  • In-memory limit order book
  • Multithreaded processing pipeline
  • CPU pinning and cache-aware layouts
  • p50, p99, p99.9 latency and throughput
  • Optional DPDK or AF_XDP experiments

Tech stack

C++20 · Linux · POSIX sockets
TCP · UDP · Multicast · epoll
Atomics · SPSC queue · Threads
Preallocated buffers · Custom allocators
perf · FlameGraph · Calibrated rdtsc
CMake · GoogleTest · Google Benchmark
Target deliverable

A simulated market-data system with an order book, packet-loss recovery, and documented end-to-end latency benchmarks.
